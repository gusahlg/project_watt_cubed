# Night log — 2026-07-05

State snapshot, decisions, and measurements from the overnight work session.
(Companion brainstorm: [IDEAS.md](IDEAS.md).)

## Where the project stands

Rendering runs entirely on our own `voxel_engine` (sibling repo): Vulkan 1.3,
dynamic rendering + sync2, 24-byte textured vertices, device-local suballocated
mesh memory, reversed-Z, engine-side frustum culling, embedded 8x8 font for all
UI. raylib is gone; the game's only dependency is the engine.

Performance on the M3 (render distance 6, 2560x1440):

| milestone | avg fps | p1 fps |
|---|---|---|
| raylib port baseline | ~110 (display-locked) | ~20 |
| + greedy meshing, streaming early-outs, culling | still display-locked | ~25 |
| + render/present decoupling (manual mailbox) | 4,981 | 2,347 |
| + review fixes (incl. one-frame-per-cycle guard) | 3,271 | 1,587 |

The decisive discovery: macOS composits drawables at the display refresh no
matter the present mode — both `RedrawRequested` and the MoltenVK drawable pool
enforce it. The fix is architectural: render into per-slot offscreen images
(fence-paced only by our own GPU work), and copy-present at the display's own
cadence. Frames that outrun presentation are rendered but dropped. `vsync on`
restores classic pacing via copy-fence backpressure.

Gameplay systems added this session: element-blended block textures (one
16x16 layer per block id, deterministic from composition, built once per
palette growth), natural-block crafting (C panel + RMB placement, shared
element stash with the inventory), hjkl menu navigation, async chunk
generation/meshing on a worker pool, WATT_BENCH harness, graphics settings
(fullscreen/vsync/MSAA/fps/render distance/FOV) with persistence and /gfx.

Two adversarial review rounds (multi-agent, every finding independently
verified twice) caught and fixed 21 real bugs across both repos — the worst:
dt-tunneling into the void after a window stall, console starving the
multiplayer heartbeat, join snapshots overflowing the frame cap, a non-ReBAR
VRAM misdetection, and an unbounded remote palette-growth vector.

## Landed tonight (all committed, reviewed, verified)

1. **3D-infinite world**: 16^3 cube chunks, `Coord = (cx, cy, cz)`. Rock
   forever downward; flying islands upward from a seeded 3D noise field whose
   threshold rises with altitude — measured island density 10.8% at y=80,
   3.0% at y=400, ~0% at y=1200, never below y=64. Island tops grass over
   dirt over stone. Save format and net protocol unchanged (round-trip test
   passed unmodified).
2. **Memory**: `ChunkData::{Uniform(BlockId), Dense(Box<[u8; 4096]>)}` — u8
   cells lean on the 256-palette cap; generation PROVES uniformity for
   sky/deep-rock. Uniform chunk ≈ 32 B vs 4 KiB dense (vs 32 KiB before the
   rework). RD-6 working set: ~450 dense (~1.8 MB) + ~1,575 uniform (~50 KB).
   The mesher fast-paths uniforms: air = empty without a scan, boxed-in rock
   = edge-slices only.
3. **Render scale** 25–200%: scaled offscreen targets + filtered blit; UI
   coordinates stay window-pixels. Settings row + `/gfx renderscale` +
   persistence. Found-and-fixed by review: sync2's COPY stage does not cover
   `vkCmdBlitImage` — the whole present chain now uses ALL_TRANSFER
   (validation-clean at 50% scale).
4. **Review round 3** (14 agents): 5 confirmed findings fixed — world-entry
   pre-generation around the restored player (was: physics vs void embeds
   the player in late-arriving terrain), border invalidation for edits in
   unloaded chunks, streaming upload dedup, blit sync, menu off-list snap.

Final numbers (M3, RD 6, 2560x1440): **3,093 avg / 1,541 p1 fps** with the
full 3D-infinite world (4,860 avg at 50% render scale). 102/102 game tests,
33/33 engine tests, validation-clean at both 100% and 50% scale.

## Engine invariants worth remembering

- Game imports Vec2/Vec3/Color/etc. from `voxel_engine` only — never `glam`
  directly (version-mismatched types would not unify).
- Swapchain is UNORM (not SRGB) to reproduce the raylib-era colors exactly.
- Texture-array layer == block id, stored in vertex color alpha (u8) — this is
  WHY the palette caps at 256. Lifting the cap means widening the vertex
  attribute or indirecting layer lookup.
- Layer 0 must always render pure white (engine immediates rely on it).
- `set_block_textures` waits for GPU idle: only call on palette growth.
- Mesh uploads mid-update are drawable the same frame; frees are deferred and
  fence-proven. Minimized windows still reclaim (reclaim_while_idle).
